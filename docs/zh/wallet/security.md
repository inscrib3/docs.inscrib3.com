# 安全和风险模型

Inscrib3 钱包是自托管的：钥匙永远不会离开设备。这消除了 Inscrib3 的保管权，但使得保护种子和审查请求变得至关重要。

::: danger
丢失助记词可能会导致资金无法追回。公开它可以让第三方控制它们。
:::

## 对于用户

- 从[官方 Chrome 网上应用店列表中安装扩展程序](https://chromewebstore.google.com/detail/inscrib3/hafphignbjdmblopkophkohgnphalclg)，或使用官方 GitHub 版本并验证`SHA256SUMS`；
- 离线存储助记词，切勿将其输入到网站或应用中；
- 在每个审批窗口检查来源、网络、地址和金额；
- 仅使用您可以承受损失的资金；
- 保持钱包更新：仅支持最新版本。

## 对于开发者

- 绝不要求用户输入助记词；
- 在建立交易之前检查活动网络；
- 将所有 BTC 金额表示为正整数 satoshis；
- 假设每个批准都可以被拒绝并处理错误；
- 始终在 PWA 回退中验证`event.origin`和`event.source`；
- 切勿使用`*`作为消息的目标源。

## 单边退出

钱包无需Ark服务器配合即可在链上追回资金。这是一条紧急路径：代币背后的每一个链外步骤都必须在链上发布，并且费用可能会超过一个小余额。首先解决会减少最近使用 VTXO 的路径，并可以限制成本。

## 报告漏洞

不要针对安全问题公开发布问题。使用存储库的[私有漏洞报告](https://github.com/inscrib3/arkade-wallet/security/advisories/new)并包含受影响的组件、复制步骤和潜在影响。

::: info
该项目不提供错误赏金。Ark协议、Ark服务器或外部依赖项中的漏洞应报告给各自的项目。
:::
